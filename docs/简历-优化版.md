## 一、为什么这样改（先看逻辑，再看文案）

你的简历现在有三个问题，改之前先说清楚：

### 问题 1：两个项目在讲同一件事，且顺序倒置

现有顺序是「接口自动化测试（2026.04-05）」排在「情感分析系统（2025.10-2026.04）」前面。
但**接口自动化测的就是情感分析系统的后端** —— 它们是同一个项目被拆成了两条，
读者会疑惑"到底做了几个项目"，而且最新最强的成果被压在下面。

### 问题 2：测试岗的核心项目，恰好是说服力最弱的那个

「对本人独立开发的 Flask 后端进行系统化测试」—— 这句话在测试岗面试里是**减分项**。
面试官的第一反应是：*你测的是你自己写的代码，那 bug 是你写的时候就知道的，不算发现能力。*

所以新版本把**测真实第三方开源项目**的 djoser 项目提为主项目，
原项目压缩为"一个项目、两条线"（系统 + 自测），既省版面又消除重复。

### 问题 3：专业技能里塞了没有项目支撑的 Playwright

你技能里写了「UI 自动化测试：Playwright（定位器、输入交互、状态断言、截图与元素可见性校验）」，
但**整个简历里没有任何项目用到 Playwright**。测试岗面试官看到这条几乎一定会问
"你的 Playwright 脚本在哪个项目里？跑一遍给我看"。

> **处理方式（已在本轮完成）**：在 djoser 项目中补充 **T08 UI 自动化模块** ——
> 用 Playwright 驱动 Django Admin 后台，14 条用例覆盖登录校验、列表搜索、编辑保存、
> 登出失效与权限边界，已实跑全部通过。
> 现在 Playwright 有项目支撑，可以放心写回技能项。

缺陷检出：  发现并复现 2 个上游真实缺陷：①当 LOGIN_FIELD 与 USERNAME_FIELD 不一致时，

抛未捕获 TypeError 返回 HTTP 500，根因定位至 djoser/serializers.py:62-68
（可写字段计算遗漏 username）。其中缺陷①经实际执行验证了上游 issue #922 中
「基于静态分析、未实际执行」的报告成立，并补充了原文未覆盖的第二处触发点。

成果：      70 条用例全部通过，单轮耗时 208 秒，零警告退出；产出含复现步骤、实际/预期
结果、行级根因与修复建议的完整缺陷报告；同步整理测试计划、用例清单与测试总结报告，
供第三方直接复用为补充测试套件。
